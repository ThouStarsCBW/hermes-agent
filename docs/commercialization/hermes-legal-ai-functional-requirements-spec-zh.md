## 1. 引言

### 1.1 编写目的

本文档将商业化规划中的产品定义、案件工作流、技术架构与合规要求，转化为**可开发、可测试、可验收**的功能需求与非功能需求，明确：

1. 系统必须提供的功能清单及其优先级（P0/P1/P2）与目标交付阶段；
2. 每个功能点的输入、处理逻辑、输出与业务规则；
3. 安全、性能、可用性、合规等非功能需求；
4. 分层质量指标与发布门禁（验收标准）。

本文档不构成法律意见；涉及执业边界、备案、等保定级等事项以专项法律意见和主管口径为准。

### 1.2 项目背景与产品定位

- **产品名称：** Hermes Legal Matter OS（案件工作操作系统；中文对外名称待定，禁止使用"自动律所"类表述）。
- **产品定位：** 持证律师监督下的、证据可追溯的案件梳理与法律协作平台。
- **首发场景：** 商业合同争议案件准备工作台（合同成立与效力、履行与违约、解除、价款/损失、担保、管辖、时效等争点簇）。
- **核心承诺：** 从原始材料到律师可审的案件工作包，重要事实逐条有证据定位，重要法律结论逐条有有效法源，任何外部动作均由有权限的人确认。
- **技术底座：** 复用 Hermes 的智能体编排循环、多模型适配、Electron 桌面端、审批机制与插件边界；新建法律控制面（Legal Control Plane）与法律领域服务（Legal Domain Services），遵循"窄核心、边缘扩展"原则，不在 Hermes 常驻核心工具 schema 中堆叠法律能力。

### 1.3 适用范围与读者对象

- **适用市场：** 中国大陆；首要客户为 5—30 人、年处理 50 件以上材料密集型案件的争议解决团队（可位于精品所、大型律所或企业法务部门）。
- **读者对象：** 产品负责人、法律产品负责人、架构师、前后端/桌面/Word 工程师、AI/检索/评测工程师、文档/OCR 工程师、安全与 SRE、QA、法务合规、解决方案与客户成功。

### 1.4 术语与缩略语

| 术语 | 含义 |
|---|---|

## 2. 总体需求

### 2.1 产品目标

| 类别 | 目标 |
|---|---|
| 北极星指标 | 每个经律师审核通过的"案件工作包"所节省的净工时（须扣除上传、纠错、等待、来源核验和审阅时间） |
| 效率目标 | 完整计入律师复核时间后，案件梳理净工时下降 ≥30% |
| 质量目标 | 外发成果虚构法条/案例为 0；重要结论来源覆盖率 100% |
| 安全目标 | 跨租户/跨案件泄露测试为 0；关键攻击成功数为 0 |
| 商业目标 | 试点期 5—8 家付费共创客户、≥25 个案件工作包；收费 V1 达 15—30 家付费机构 |

### 2.2 产品范围

#### 2.2.1 范围内（首发必须稳定生产）

1. 材料清单与证据编号建议；
2. 当事人/关联方/合同关系图；
3. 带页码来源的事实时间线；
4. 争点树及请求权候选；
5. 要件—事实—证据—反证—缺口矩阵；
6. 对方可能主张与矛盾点分析；
7. 律师确认范围内的法规、案例检索与验证；
8. 起诉状、答辩状、代理意见或法律备忘录的**待审**初稿。

#### 2.2.2 明确不做（MVP 与收费 V1 均禁止）

1. 面向公众的无人法律咨询或"AI 律师"人格化陪伴；
2. 自动接受委托、报价、签约、收费或形成律师—客户关系；
3. 自动向法院、仲裁机构、客户、对方或社交媒体提交/发送内容；
4. 胜诉率、量刑、赔偿额的确定性预测或保证；
5. 代替律师决定诉讼请求、和解底线、证据取舍和是否披露；
6. 自动改写、覆盖或删除证据原件；
7. 用客户案件材料训练通用模型（除非存在单独、明确、可撤回的合法授权且完成影响评估）；
8. 在普通 SaaS 环境处理国家秘密、工作秘密或客户认定需要专门保密系统的材料；
9. 让案件智能体访问宿主机终端、个人网盘、个人邮箱或无关案件。

#### 2.2.3 案件类型边界

| 案件类型 | 策略 |
|---|---|
| 商业合同争议 | 首发 |
| 建设工程/工程款、劳动争议 | 第二案由候选，达扩张条件后评估 |
| 刑事、婚姻家事/未成年人 | MVP 排除 |
| 国家秘密/工作秘密相关 | 普通产品**永久禁止接收**，创建案件时强制询问并硬阻断 |

### 2.3 用户角色与权限边界

| 角色 | 可做 | 不可做 |
|---|---|---|
| 案件负责人/主办律师 | 设定范围、确认事实、批准策略和外发 | 绕过伦理墙访问其他团队案件 |
| 承办律师 | 上传、校对、创建任务、编辑工作成果 | 最终对外提交（除非被授权） |
| 律师助理/实习人员 | 整理、标注、提出修订 | 批准最终法律结论 |
| 知识管理员 | 管理模板、律所知识和法源授权 | 查看无授权案件事实 |
| 合规/安全管理员 | 查看策略、告警和审计元数据 | 默认读取案件正文 |
| 客户协作用户 | 在受控门户查看/补充指定材料 | 浏览内部策略、对方画像、其他客户数据 |
| 系统/模型管理员 | 管理模型版本、供应商和容量 | 默认解密案件内容 |
| 外部专家 | 查看被案件负责人授权的最小材料包 | 下载全部案件或转授权 |

权限判定规则：`有效权限 = 租户策略 ∩ 案件策略 ∩ 角色卡 ∩ 当前任务 ∩ 用户授权`，**默认拒绝**，且必须在服务端强制，不得依赖前端隐藏或提示词。

### 2.4 总体业务流程与质量门禁

端到端工作流分 13 个阶段，门禁 G0—G5 由人工在实质节点放行：

| 阶段 | 系统动作 | 人工责任 | 主要产物 | 门禁 |
|---|---|---|---|---|
| 0 案件创建 | 创建客户/案件、分配负责人、选择保留与部署策略 | 确认委托范围与冲突检查状态 | 案件授权单 | G0 授权门 |
| 1 材料接收 | 病毒/格式检查、哈希、原件封存、清单化 | 确认材料来源与完整性 | 原件清单 | G1 完整性门 |
| 2 解析与 OCR | 文本层、表格、图片、手写/印章检测、页坐标 | 抽检低置信页 | 可检索派生件 | G1 |
| 3 实体归一 | 提取人、组织、合同、账号、金额、日期；合并别名 | 确认同名/别名与关联关系 | 实体表/关系图 | G2 事实门 |
| 4 事实时间线 | 生成事件、来源、时间精度和冲突 | 接受、修改、驳回关键事实 | 已确认时间线 | G2 |
| 5 争点与要件 | 根据主张候选建立要件框架 | 主办律师确定分析范围 | 争点树/要件矩阵 | G2 |
| 6 证据映射 | 支持/反对证据映射到事实和要件 | 判断证明力与证据风险 | 证据矩阵/缺口清单 | G2 |
| 7 法律研究 | 检索时点有效的法条、解释、案例及反向权威 | 确认法源、层级和适用性 | 检索备忘录 | G3 法源门 |
| 8 对抗分析 | 模拟对方主张、替代解释与不利事实 | 判断是否采纳并确定应对 | 对抗审查表 | G3 |
| 9 起草 | 仅基于"律师已确认事实 + 已验证法源"生成 | 编辑策略、措辞和请求 | 待审文书 | G4 交付门 |
| 10 验证 | 逐句事实/法源/计算/格式检查 | 处理所有阻断项 | 验证报告 | G4 |
| 11 导出/发送 | 生成带版本、来源和 AI 标识策略的文件 | 最终批准；高风险双人复核 | 最终文件/导出清单 | G5 外部动作门 |
| 12 复盘与归档 | 计算净工时、采纳率、错误、成本；执行保留策略 | 确认知识提炼范围 | 复盘报告 | 归档门 |

### 2.5 系统总体结构

系统由七个平面构成，代码上分为三层（Hermes Core Fork/Package、Legal Control Plane、Legal Domain Services）：

1. **身份与案件控制面**：SSO/MFA/SCIM、五级范围、RBAC+ABAC、伦理墙、临时访问与 Break-glass；
2. **证据数据平面**：原件（WORM）、派生件、元数据/权限/工作流、索引、事实证据图、工作成果、审计的分离存储；
3. **法律知识平面**：公共/授权法律知识库与案件私有知识库两套语料严格分离；
4. **智能体执行平面**：确定性工作流引擎包裹 Hermes 循环，角色化智能体 + 任务契约 + 预算；
5. **模型网关**：区域/留存/训练/脱敏/路由/降级策略的执行与记录；
6. **治理与审计平面**：全量审计事件、评测门禁、告警、保留与法律保全；
7. **体验与连接器平面**：Electron 桌面 + Web 工作台 + Word 插件，分级连接器。

### 2.6 需求优先级定义

| 优先级 | 含义 | 对应规划 |
|---|---|---|
| P0 | 闭环必需，Alpha/试点必须完成 | 规划 §4.4 P0 |
| P1 | 形成付费差异，收费 V1 完成 | 规划 §4.4 P1 |
| P2 | 规模化能力，企业化阶段 | 规划 §4.4 P2 |
| 暂不排期 | 自动诉讼结果预测、全自动向法院提交、公众端服务市场、自研基础大模型、自建全国全量法律数据库 | 规划 §4.4 |

## 3. 功能需求

> 编号约定：FR-xx-yy（模块-功能点）。每条功能点给出描述、优先级与关键业务规则/验收要点。

### FR-01 组织与身份管理

**模块概述：** 提供机构入驻、组织同步与统一认证，是所有权限判定的身份基础。

| 编号 | 功能点 | 优先级 | 业务规则与验收要点 |
|---|---|---|---|
| FR-01-01 | 机构/租户开通与五级范围管理（租户→办公室→团队→客户→案件） | P0 | 任意数据对象必须可归入唯一五级路径；不存在"无租户"数据 |
| FR-01-02 | 企业 SSO（OIDC/SAML）、MFA 强制 | P0 | 支持主流 IdP；MFA 不可由租户关闭（V1 起） |
| FR-01-03 | SCIM 或组织目录同步 | P1 | 人员离职/调岗后权限自动回收，提供回收时效指标 |
| FR-01-04 | RBAC 角色管理 + ABAC 属性策略（案件属性、数据级别、地域、设备、时间） | P0 | 策略变更即时生效并留审计事件；提供策略模拟判定接口 |
| FR-01-05 | 临时访问授权：目的、期限、批准人、自动回收 | P1 | 到期自动失效；超期未回收为高危告警 |
| FR-01-06 | Break-glass 紧急访问：双人批准、强告警、事后审计 | P1 | 每次触发必须生成事后复核工单 |

### FR-02 案件与权限管理（含伦理墙）

**模块概述：** 案件是权限、数据与工作流的边界单元；伦理墙与冲突标记为强制控制。

| 编号 | 功能点 | 优先级 | 业务规则与验收要点 |
|---|---|---|---|
| FR-02-01 | 案件创建向导：客户、案由簇、负责人、保留策略、部署策略、法律时点 | P0 | 创建必须完成授权确认（G0），否则案件不可接收材料 |
| FR-02-02 | 案件接收清单与权限确认 | P0 | 记录委托人、授权范围、数据处理依据 |
| FR-02-03 | 利益冲突标识与伦理墙：客户/对方/关联方冲突标记，阻断冲突团队访问 | P0 | 服务端强制；跨墙检索/读取负向测试通过率 100%（泄露为 0） |
| FR-02-04 | 高敏案件强制询问与硬阻断：国家秘密、工作秘密、侦查秘密、未公开重大交易、核心技术秘密、客户特别限制 | P0 | 命中后自动阻断普通部署；不允许"点击免责声明继续"绕过 |
| FR-02-05 | 案件数据级别标记（L0—L4，见 §5.2），文件级、字段级、任务级三级打标 | P0 | 数据级别决定模型路由与部署形态（见 FR-16） |
| FR-02-06 | 案件归档与关闭：执行保留策略、导出结案包 | P0 | 归档后默认只读；重开需负责人审批 |

### FR-03 证据摄取与保全链

**模块概述：** 将杂乱卷宗转化为可验证、可定位、不可篡改的案件材料库。流程：接收 → 隔离检查 → 哈希封存 → OCR/解析 → 质量评分与抽检 → 去重/版本/附件关系 → 实体候选 → 律师确认 → 案件索引与事实证据图。

| 编号 | 功能点 | 优先级 | 业务规则与验收要点 |
|---|---|---|---|
| FR-03-01 | 多通道材料接收（本地上传、受控连接器、客户门户），统一进入隔离区 | P0 | 真实案件材料不得经普通聊天平台网关流入 |
| FR-03-02 | 隔离区检查：文件类型、恶意文件（AV/CDR）、宏/脚本/外链/嵌入对象、压缩包递归与解压炸弹、资源限制 | P0 | 可疑文件不进入主存储；解析器沙箱化运行 |
| FR-03-03 | 原件哈希（SHA-256）与 WORM 不可变封存、独立原件 ID | P0 | 原件永不被 OCR 结果替换；哈希/页数一致性 100%（Alpha 门禁） |
| FR-03-04 | OCR 与版面解析：文本层、表格、图片、手写/印章检测、页级版面坐标 | P0 | 每个摘录可定位到 `document_id + page + bounding_box + text_hash` |
| FR-03-05 | 页级质量评分与人工抽检队列（低清扫描、手写、印章、复杂表格、金额列） | P0 | 低质页可识别并 100% 转人工 |
| FR-03-06 | 去重与版本/附件关系：相同哈希直接去重；近似重复只提示不自动删除；新版本入新对象并保留差异与来源 | P0 | 禁止自动删除任何近似件 |
| FR-03-07 | 证据编号建议与材料清单（文件名、来源、接收人、接收时间、哈希、页数、处理状态） | P0 | 关键文件 100% 入清单 |
| FR-03-08 | 证据包导出：附文件清单、哈希和处理历史 | P0 | 导出清单可被独立校验工具复核 |

### FR-04 实体抽取与归一

| 编号 | 功能点 | 优先级 | 业务规则与验收要点 |
|---|---|---|---|
| FR-04-01 | 实体抽取：人物、组织、合同、账号、金额、日期 | P0 | 金额和日期以字段级评测；实体必须带来源锚点 |
| FR-04-02 | 实体归一与别名合并 | P0 | 合并/拆分由人工确认，保留操作前后版本 |

## 4. 非功能需求

### 4.1 NFR-01 安全需求（威胁模型驱动）

| 威胁 | 核心控制（必备） | 监测 |
|---|---|---|
| 跨案件/跨租户泄露 | 强制案件作用域、行级安全、独立密钥、负向测试 | 蜜标/金丝雀、异常查询告警 |
| 文档提示注入 | 文档内容永不成为控制指令、工具白名单、无自由外网 | 注入命中、异常工具意图 |
| 恶意文件 | 隔离沙箱、AV/CDR、资源限制、解析器补丁 | 隔离失败与解析异常 |
| 模型供应商泄露 | DPA、零训练/最短留存、区域路由、专属端点 | 供应商清单与调用审计 |
| 内部人员越权 | 职责分离、JIT、双人审批、字段加密 | 大量读取/异常时段告警 |
| 插件供应链 | 签名、审核、SBOM、版本锁定、隔离进程 | 完整性与权限变化 |
| 错误/过期法源 | 权威核验、时点版本、双源校验、发布门禁 | 引证失败率、过期命中 |
| 证据污染 | 原件 WORM、派生件分离、哈希链 | 哈希校验与版本告警 |
| 审计泄密 | 最小化明文、字段加密、分层审计、保留策略 | 审计访问告警 |
| 自动外发 | 生产无外发工具、待发送包、不可绕过人审 | 所有出口事件 |

### 4.2 NFR-02 性能与容量

- 关键交互（打开原件页、时间线定位、问答响应）应满足律师连续工作不中断的体验要求；具体阈值在 Alpha 期按 50 案金标压测标定；
- 预算同时限制 Token、时间、并发、模型成本与外部调用；超大文件、重试风暴为主要毛利与性能风险，须有配额与降级；
- 所有关键处理任务幂等、可重试，不得因重试重复修改事实。

### 4.3 NFR-03 可用性与灾备（收费 V1 工程目标）

- SaaS 月度可用性目标 99.9%，私有化按合同约定；
- RPO：案件元数据 ≤5 分钟；原件写入即多副本；
- RTO：核心查看/导出 ≤4 小时，AI 增强能力可降级；
- 每季度恢复演练；每次重大模型/解析器升级保留回滚版本。

### 4.4 NFR-04 合规需求

1. **执业边界：** 法律意见、诉讼文书、客户回复必须绑定负责人与批准记录；营销不得承诺结果、胜诉率或"替代律师"；
2. **个人信息保护：** 目的限定、最小必要、PIPIA（敏感个人信息、自动化决策、委托处理、对外提供、跨境场景）、分类/加密/去标识/最小权限/培训/应急预案/定期合规审计；
3. **委托处理：** DPA、子处理者清单、模型供应商附表，处理记录至少保存三年；
4. **数据跨境：** 原始案件材料默认不出境；涉个人信息出境履行合法性、必要性、告知、单独同意义务；
5. **生成内容标识：** 按《人工智能生成合成内容标识办法》执行显式/隐式标识、导出文件标识、日志与备案材料要求；
6. **备案与资质：** 算法备案、安全评估、ICP/EDI 等按实际服务范围由专项法律意见确认，不凭"B2B"标签自动豁免；
7. **等保：** 收费 SaaS 按等保三级能力目标设计，正式定级、备案与测评依主管要求执行；安全基线映射 GB/T 22239—2019、GB/T 43697—2024、GB/T 35273—2020、GB/T 45654—2025。

### 4.5 NFR-05 工程与可维护性规则

1. 法律能力优先作为业务工具、服务门控工具、插件或 MCP 提供，不随意增加 Hermes 常驻核心工具；
2. 系统提示词在会话内保持字节稳定；案件事实、权限和任务放在动态数据对象中（保障提示缓存与权限可撤销）；
3. 权限与数据过滤必须在服务端强制；
4. 测试断言行为契约与隔离不变量，不冻结会变化的模型枚举、版本号或计数；
5. 涉及身份、权限、远端存储和文件 I/O 的功能必须有真实路径 E2E；
6. 重大依赖升级、模型切换、法源更新均触发回归；
7. 任何"临时绕过"必须有到期日、风险接受人和自动告警；
8. SBOM 与开源许可证扫描覆盖 Python、Node/Electron、模型 SDK、OCR、字体、文档解析与数据库依赖。

## 7. 约束与假设

### 7.1 约束

1. **法律约束：** 律师法执业边界、保密与冲突义务；生成式 AI 相关办法按产品形态适用；涉国家秘密案件永久禁止进入普通产品；
2. **技术约束：** 提示缓存稳定性（系统提示词会话内字节稳定）；窄核心原则；生产环境无通用终端/YOLO/未签名插件；
3. **数据约束：** 法源内容必须合法授权；评测数据需授权 + 去标识 + 隔离；客户案件材料默认不用于训练；
4. **商业约束：** 试点期不建第二案由；私有化定制必须配置化/插件化，例外单独报价并经架构委员会批准。

### 7.2 假设

- 首批 5—8 家共创律所各提供 3—5 个有合法授权的案件；至少 20 个代表案件样本可合法用于受控开发/评测；
- 核心法源存在可行授权路径；目标场景中材料梳理/检索/初稿占基线工时 ≥30%；
- 价格、预算、渗透率与收入均为规划假设，非承诺；需求优先级与门禁数值将在试点中按案由难度重新校准。

## 8. 验收标准与质量门禁

### 8.1 分层质量指标（收费 V1 门禁）

| 层级 | 指标 | 门禁 |
|---|---|---|
| 摄取 | 文件成功率、页数一致、OCR 字符/字段质量 | 关键文件 100% 入清单；低质页可识别并转人工 |
| 事实 | 关键实体召回、事件准确、金额/日期准确 | 金额和日期字段级评测；重要事实必须有人审 |
| 来源 | 事实锚点覆盖、页码可达、摘录一致 | 外发重要命题来源覆盖率 100% |
| 法源 | 引用存在、有效状态、时点、层级、命题支持 | 虚构引证 0；阻断所有失效/无法验证引用 |
| 推理 | 要件覆盖、反方观点、未知项识别 | 两名律师盲评；不能只由模型评分 |
| 文书 | 事实一致、请求和计算、格式、语言 | 所有阻断项清零后才可批准 |
| 安全 | 跨租户泄露、越权工具、提示注入 | 关键攻击成功数 0 |
| 效率 | 总工时、人工复核工时、返工率 | 净工时下降 ≥30%，不牺牲质量 |
| 使用 | 律师采纳、周活、工作包完成率 | 试点工作包完整完成率 ≥70% |

### 8.2 阶段门禁摘要

- **Alpha 门禁：** 跨案件/租户泄露测试为 0；原件哈希和页数一致性 100%；关键事实来源覆盖 100%；律师 30 分钟内学会校对时间线；5 个案件全流程完成且无高严重度安全事件；
- **试点门禁：** 虚构法条/案例 0；重要命题来源覆盖 100%；盲评质量不低于人工流程；中位净工时下降 ≥30%；每案 ≥3 条有价值的自动发现；人工复核不超过被替代基线工时的 50%；
- **试点评分卡：** 净效率 25%、事实质量 15%、来源与引证 20%、复核体验 10%、缺口发现 10%、安全合规 15%、商业意愿 5%；总分 <75 不进入年单，安全/虚构引证红线一票否决。

### 8.3 外发前律师审核清单（系统应固化为 G5 检查项）

委托范围与当事人/程序阶段正确；关键事实均为律师确认状态且来源可打开；未将系统推论写成确定事实；金额/利息/期限/时效经确定性工具重算；法规在目标时点有效且地域层级适用；案例真实且层级表述准确；不利事实、反向权威与主要反方主张已考虑；证据目录与原件编号一致；隐私与披露范围符合授权；AI 标识策略已按用途应用；与已批准版本差异已复核；负责人/复核人/导出对象/文件哈希已记录。

### 8.4 指标防作弊

- 节省工时必须包含复核与返工；采纳率不得把"用户未修改"自动视为正确（需抽样复核）；
- 引用覆盖须检查脚注是否支持具体命题；工作包数量须达最低完整度；
- 安全事件按严重度与影响呈现；ARR 与一次性实施收入分开；私有化大单不得掩盖标准 SKU 留存与毛利问题。
